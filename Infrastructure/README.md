# Infrastructure Layer Documentation

## 1. Layer Overview

### Purpose
The Infrastructure layer handles data access, external service integration, and technical implementations. It contains the database context, Entity Framework migrations, repository implementations, ASP.NET Identity configuration, and data seeding logic.

### Position
This is the outermost layer in the Clean Architecture. It implements the interfaces defined in the Application layer and provides concrete implementations for data access, identity management, and external integrations.

### Dependencies
- **Depends on**: Domain layer (entities, enums, DTOs)
- **External dependencies**: Microsoft.AspNetCore.Identity.EntityFrameworkCore (10.0.10), Microsoft.EntityFrameworkCore (10.0.10), Microsoft.EntityFrameworkCore.SqlServer (10.0.10), Microsoft.EntityFrameworkCore.Tools (10.0.10), Microsoft.EntityFrameworkCore.Design (10.0.10), Microsoft.Extensions.DependencyInjection (10.0.10)
- **Depended by**: Application layer (uses repositories, Identity, DbContext)

### Key Principles
- **Repository Pattern**: Abstracts data access behind repository interfaces
- **Unit of Work Pattern**: Manages transactions and repository coordination
- **Dependency Inversion**: Implements interfaces defined in Application layer
- **Separation of Concerns**: Data access logic isolated from business logic

## 3. Subfolder Summaries

### DbContext/
- **Folder Name**: DbContext
- **Purpose**: Database context and Entity Framework configuration
- **Contents**: AppDbContext.cs
- **Relationships**: Used by repositories for data access. Configured in WebApplication startup. Defines DbSets for entities.

### Identity/
- **Folder Name**: Identity
- **Purpose**: ASP.NET Core Identity configuration and custom user/role entities
- **Contents**: ApplicationUser.cs, ApplicationRole.cs
- **Relationships**: Used by Identity managers (UserManager, RoleManager). Mapped to database tables by AppDbContext.

### Identity/Claims/
- **Folder Name**: Claims (subfolder of Identity)
- **Purpose**: Claims management for authorization
- **Contents**: AppUserClaimsPrincipalFactory.cs, ClaimStore.cs, ClaimsModel.cs
- **Relationships**: Used by RoleClaimsService. ClaimStore defines available claims. Factory adds custom claims to user identity.

### InterfacesDB/
- **Folder Name**: InterfacesDB
- **Purpose**: Repository and Unit of Work interface definitions
- **Contents**: IGenericRepository.cs, IUnitOfWork.cs
- **Relationships**: Implemented by Repositories folder. Used by Application layer services.

### InterfacesDB/RemainInterfacesDB/
- **Folder Name**: RemainInterfacesDB (subfolder of InterfacesDB)
- **Purpose**: Additional repository interfaces for specific entities
- **Contents**: IRoleRepository.cs
- **Relationships**: Implemented by RemainRepositories. Extends IGenericRepository.

### Migrations/
- **Folder Name**: Migrations
- **Purpose**: Entity Framework database migrations
- **Contents**: Migration files for schema changes and snapshot
- **Relationships**: Generated by EF Core tools. Applied to database on startup. Includes:
  - ConfigureIdentityCookie (20260729084110)
  - AddLogsHistoryTable (20260729144857)
  - Update_TableRoleForAddSoftDelete (20260809144434)

### Repositories/
- **Folder Name**: Repositories
- **Purpose**: Repository implementations for data access
- **Contents**: GenericRepository.cs, UnitOfWork.cs
- **Relationships**: Implement interfaces from InterfacesDB. Used by Application layer services.

### Repositories/RemainRepositories/
- **Folder Name**: RemainRepositories (subfolder of Repositories)
- **Purpose**: Specific repository implementations
- **Contents**: RoleRepository.cs
- **Relationships**: Implements IRoleRepository. Extends GenericRepository.

## 4. Cross-Layer Relationships

### What this layer exposes:
- **DbContext**: AppDbContext for database operations
- **Identity Entities**: ApplicationUser, ApplicationRole for authentication/authorization
- **Repositories**: GenericRepository, RoleRepository, UnitOfWork for data access
- **Interfaces**: IGenericRepository, IUnitOfWork, IRoleRepository for dependency inversion
- **Claims**: ClaimStore, ClaimsModel, AppUserClaimsPrincipalFactory for authorization
- **Seeder**: Seeder for initial data seeding

### What this layer consumes:
- **From Domain Layer**: Entities (LogsHistory, ClaimSelection), Enums
- **External Libraries**: Entity Framework Core, ASP.NET Core Identity, SQL Server provider

### Data Flow:
- **Input**: Application layer services call repository methods
- **Processing**: Repositories use DbContext to query/modify database
- **Output**: Repositories return entities or DTOs to Application layer
- **Storage**: DbContext persists changes to SQL Server database via EF Core

## 5. Detailed File-by-File Documentation

### DbContext/AppDbContext.cs
- **Location**: `DbContext/AppDbContext.cs`
- **Type**: DbContext class
- **Purpose**: Entity Framework database context for the application
- **Role**: Manages database connection, entity mappings, and DbSet configurations
- **Key Members**:
  - `AppDbContext()`: Parameterless constructor
  - `AppDbContext(DbContextOptions<AppDbContext>)`: Constructor with options
  - `LogsHistories`: DbSet for LogsHistory entity
- **Dependencies**: Domain.Entites (typo - should be Entities), Domain.Entities, Infrastructure.Identity, Microsoft.AspNetCore.Identity.EntityFrameworkCore, Microsoft.EntityFrameworkCore
- **Impact**: Core database context used by all repositories. Changes affect database schema and Entity Framework behavior.
- **Notes**: Inherits from IdentityDbContext<ApplicationUser, ApplicationRole, string>. Has namespace typo "Domain.Entites". Only has LogsHistories as custom DbSet - other entities managed by IdentityDbContext.

### Identity/ApplicationRole.cs
- **Location**: `Identity/ApplicationRole.cs`
- **Type**: Identity entity class
- **Purpose**: Extends ASP.NET Core Identity Role with custom properties
- **Role**: Represents application roles with additional business properties
- **Key Members**:
  - `ApplicationRole()`: Default constructor
  - `ApplicationRole(string roleName)`: Constructor with role name
  - `RoleNumber`: Nullable int for role ordering/priority
  - `isDeleted`: Nullable bool for soft delete pattern
- **Dependencies**: Microsoft.AspNetCore.Identity
- **Impact**: Used by RoleManager and RoleRepository. Changes affect role management and database schema.
- **Notes**: Property naming uses lowercase "isDeleted" (non-standard C# convention). Default value for isDeleted is false. Inherits all IdentityRole properties (Id, Name, NormalizedName, ConcurrencyStamp).

### Identity/ApplicationUser.cs
- **Location**: `Identity/ApplicationUser.cs`
- **Type**: Identity entity class
- **Purpose**: Extends ASP.NET Core Identity User with custom properties
- **Role**: Represents application users with additional business properties
- **Key Members**:
  - `FullName`: Nullable string for user's full name
- **Dependencies**: Microsoft.AspNetCore.Identity
- **Impact**: Used by UserManager and authentication. Changes affect user management and claims.
- **Notes**: Inherits all IdentityUser properties (Id, UserName, NormalizedUserName, Email, NormalizedEmail, EmailConfirmed, PasswordHash, SecurityStamp, ConcurrencyStamp, PhoneNumber, PhoneNumberConfirmed, TwoFactorEnabled, LockoutEnd, LockoutEnabled, AccessFailedCount). Minimal custom properties - may need expansion.

### Identity/Claims/AppUserClaimsPrincipalFactory.cs
- **Location**: `Identity/Claims/AppUserClaimsPrincipalFactory.cs`
- **Type**: ClaimsPrincipalFactory class
- **Purpose**: Custom claims principal factory to add custom claims to user identity
- **Role**: Extends UserClaimsPrincipalFactory to add FullName claim to user identity
- **Key Members**:
  - `AppUserClaimsPrincipalFactory(UserManager, RoleManager, IOptions<IdentityOptions>)`: Constructor
  - `GenerateClaimsAsync(ApplicationUser)`: Overrides to add custom claims
- **Dependencies**: Microsoft.AspNetCore.Identity, Microsoft.Extensions.Options, System.Security.Claims
- **Impact**: Affects what claims are available in HttpContext.User. Changes affect authentication and authorization.
- **Notes**: Adds "FullName" claim if user has FullName. Has commented code for UserTypeId claim (legacy). Arabic comments in code.

### Identity/Claims/ClaimStore.cs
- **Location**: `Identity/Claims/ClaimStore.cs`
- **Type**: Static class
- **Purpose**: Centralized repository of available system claims organized by module
- **Role**: Defines all available claims in the system for role-based authorization
- **Key Members**:
  - `RolesClaimsList`: List of claims for role management (ViewRoles, CreateRole, EditRole, DeleteRole, ManageRoleClaims)
  - `UsersClaimsList`: List of claims for user management (ViewUsers, CreateUser, EditUser, DeleteUser, ResetPassword)
  - `MessagesClaimsList`: List of claims for messaging (ViewMessages, SendMessages)
- **Dependencies**: System.Security.Claims
- **Impact**: Used by RoleClaimsService to build claim selection UI. Changes affect available permissions in the system.
- **Notes**: All claim values are in Arabic. Claim types are in English. Static lists - not database-driven. SettingsClaimsList referenced in ClaimsModel but not defined here.

### Identity/Claims/ClaimsModel.cs
- **Location**: `Identity/Claims/ClaimsModel.cs`
- **Type**: Data model class
- **Purpose**: Model for transferring claims data between layers
- **Role**: Groups claims by module for role claim management
- **Key Members**:
  - `RoleId`: Nullable string for role ID
  - `RolesClaimsList`: List of ClaimSelection for role claims
  - `UsersClaimsList`: List of ClaimSelection for user claims
  - `MessagesClaimsList`: List of ClaimSelection for message claims
  - `SettingsClaimsList`: List of ClaimSelection for settings claims (not used in ClaimStore)
- **Dependencies**: Domain.Entites (typo - should be Entities)
- **Impact**: Used in RoleClaimsService for claim management operations. Changes affect claim management API.
- **Notes**: Uses ClaimSelection from Domain layer. Has SettingsClaimsList property but ClaimStore doesn't define SettingsClaimsList. Namespace typo "Domain.Entites".

### InterfacesDB/IGenericRepository.cs
- **Location**: `InterfacesDB/IGenericRepository.cs`
- **Type**: Generic interface
- **Purpose**: Defines contract for generic repository operations
- **Role**: Provides standard CRUD and query operations for any entity type
- **Key Members**:
  - `Table`: IQueryable for read-only queries
  - `Query(bool)`: IQueryable with optional tracking
  - `GetByIdAsync(object, bool, CancellationToken)`: Get by ID
  - `GetByIdAsync(int, bool, CancellationToken)`: Get by int ID
  - `GetAsync(Expression, string?, bool, CancellationToken)`: Get with filter and includes
  - `GetByIdAsync(Expression, string?, bool, CancellationToken)`: Get by predicate
  - `GetFirstOrDefaultAsync(Expression, string?, bool, CancellationToken)`: Get first or default
  - `GetByColumnAsync(Expression, string?, bool, CancellationToken)`: Get by column
  - `GetAllAsync(Expression?, Func, string?, bool, int?, CancellationToken)`: Get all with optional filtering, ordering, pagination
  - `GetPagedAsync(int, int, Expression?, Func, string?, bool, CancellationToken)`: Get paged results
  - `Any(Expression)`: Check if any exists (sync)
  - `AnyAsync(Expression, CancellationToken)`: Check if any exists (async)
  - `CountAsync(Expression?, CancellationToken)`: Count entities
  - `AddAsync(T, CancellationToken)`: Add entity
  - `CreateAsync(T, CancellationToken)`: Add and save
  - `AddRangeAsync(IEnumerable, CancellationToken)`: Add multiple entities
  - `Update(T)`: Update entity
  - `UpdateAsync(T, CancellationToken)`: Update and save
  - `UpdateRange(IEnumerable)`: Update multiple entities
  - `UpdateRangeAsync(IEnumerable, CancellationToken)`: Update multiple and save
  - `Remove(T)`: Remove entity
  - `DeleteAsync(T, CancellationToken)`: Remove and save
  - `RemoveRange(IEnumerable)`: Remove multiple entities
  - `DeleteRangeAsync(IEnumerable, CancellationToken)`: Remove multiple and save
  - `SaveAsync(CancellationToken)`: Save changes
- **Dependencies**: Infrastructure.Repositories, System.Linq.Expressions
- **Impact**: Core interface for all data access. Changes affect all repository implementations and services.
- **Notes**: Comprehensive interface with both sync and async methods. Some method names are redundant (GetByIdAsync overloaded). Depends on Infrastructure.Repositories (circular dependency concern).

### InterfacesDB/IUnitOfWork.cs
- **Location**: `InterfacesDB/IUnitOfWork.cs`
- **Type**: Interface
- **Purpose**: Defines contract for Unit of Work pattern to manage transactions
- **Role**: Coordinates multiple repository operations within a single transaction
- **Key Members**:
  - `Users`: GenericRepository for ApplicationUser
  - `GetRepository<T>()`: Get repository for any entity type
  - `SaveChangesAsync()`: Async save changes
  - `SaveChanges()`: Sync save changes
- **Dependencies**: Infrastructure.Identity, System
- **Impact**: Used by services to coordinate data operations. Changes affect transaction management.
- **Notes**: Implements IDisposable. Provides Users repository as a convenience property. Generic GetRepository method for other entities.

### InterfacesDB/RemainInterfacesDB/IRoleRepository.cs

## 6. Patterns and Best Practices

### Design Patterns Used:
- **Repository Pattern**: GenericRepository and specific repositories abstract data access
- **Unit of Work Pattern**: UnitOfWork coordinates multiple repository operations
- **Generic Programming**: IGenericRepository and GenericRepository work with any entity type
- **Factory Pattern**: AppUserClaimsPrincipalFactory creates claims principals
- **Static Repository Pattern**: ClaimStore as static claim definitions

### Coding Standards:
- **Async/Await**: Most database operations use async methods
- **Dependency Injection**: Repositories inject DbContext via constructor
- **Interface Segregation**: Separate interfaces for generic and specific repositories
- **Caching**: UnitOfWork caches repository instances
- **Tracking Control**: AsNoTracking by default for read operations

### Common Patterns:
- **Soft Delete Pattern**: ApplicationRole has isDeleted flag
- **Claims-Based Authorization**: ClaimStore defines system permissions
- **Migration Strategy**: EF Core migrations for schema changes
- **Seeding**: Seeder class for initial data

## Known Issues and Architectural Concerns:

1. **Namespace Typos**:
   - AppDbContext uses "Domain.Entites" instead of "Domain.Entities"
   - ClaimsModel uses "Domain.Entites" instead of "Domain.Entities"

2. **Security Issues**:
   - Seeder.cs has hardcoded credentials (admin/Super@123, master/Master@123)
   - Passwords should be in secure configuration or key vault
   - Default credentials are a security risk

3. **Logical Operator Precedence Bugs**:
   - RoleRepository.GetActiveRolesAsync: `r.isDeleted == null || r.isDeleted == false`
   - Should be `r => (r.isDeleted == null || r.isDeleted == false)` due to operator precedence when combined with other conditions

4. **Circular Dependency Concern**:
   - IGenericRepository depends on Infrastructure.Repositories namespace
   - Interface should not depend on implementation namespace

5. **Incomplete Implementation**:
   - ClaimsModel has SettingsClaimsList property but ClaimStore doesn't define SettingsClaimsList
   - AppUserClaimsPrincipalFactory has commented code for UserTypeId claim

6. **Naming Conventions**:
   - "isDeleted" property uses lowercase (non-standard C# convention)
   - "RemainInterfacesDB" and "RemainRepositories" naming is unusual
   - Should be "AdditionalInterfacesDB" or "SpecificInterfacesDB"

7. **Database Creation Strategy**:
   - Seeder uses EnsureCreated() which doesn't use migrations
   - Should use Migrate() to apply migrations instead

8. **Missing Properties**:
   - ApplicationUser only has FullName custom property
   - May need additional properties for business requirements

9. **Hardcoded Claim Values**:
   - ClaimStore has hardcoded claim lists
   - Should be database-driven for flexibility

10. **Migration Files**:
    - Migration files are auto-generated and should not be manually edited
    - Designer.cs files are auto-generated
